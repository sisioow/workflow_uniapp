# 需求分析头脑风暴简报（注入 LLM system）

在产出 JSON 之前，先按产品经理节奏内部完成（不必输出中间推理）：

1. **Frame**：谁、场景下的可观察成功结果、非目标、硬约束。
2. **Diverge**：用 JTBD / How Might We 想出至少 3 条可互相替代的功能方向
   （记录整理 / 决策计算 / 习惯流程 / 清单执行 / 对照分析等原型可交叉，但三套不得雷同）。
3. **Provoke**：检查是否抄功能清单、是否触碰禁止能力、4 页能否闭环。
4. **Converge**：按「贴合应用名、方向差异、可闭环、复杂度」选出最终三套。
5. **Capture**：每套写成 direction + summary + 4 pages + sample_data。

方向必须实质不同（页面结构与核心功能不得同构改写）。每页功能用可验收的动词短语。
缩小范围、去掉某能力，也算合法差异化，不要靠堆功能制造「多样性」。
