# 需求分析头脑风暴简报（注入 LLM system）

在产出 JSON 之前，先按产品经理节奏内部完成（不必输出中间推理）：

1. **Frame**：谁、场景下的可观察成功结果、非目标、硬约束。
2. **Diverge**：用 JTBD / How Might We 想出至少 3 条可互相替代的功能方向
   （记录整理 / 决策计算 / 习惯流程 / 清单执行 / 对照分析等原型可交叉，但三套不得雷同）。
3. **Provoke**：检查是否抄功能清单、是否触碰禁止能力、4 页能否闭环、是否过于单薄。
4. **Converge**：按「贴合应用名、方向差异、可闭环、完整度」选出最终三套。
5. **Capture**：每套写成完整需求包：direction + 2~3 句 summary + 4 pages（每页 5~8 条完整功能点 + 含二级页的 description）+ 至少 6 条 sample_data。

方向必须实质不同（页面结构与核心功能不得同构改写）。功能点必须是可验收的完整能力描述，禁止「添加 / 删除 / 查看」这类单动词。
每一套都要能独立当一款工具用：进入、完成主任务、回看调整、形成闭环。不要靠堆无关功能制造「多样性」，但也不要把方案裁成演示级小品。
